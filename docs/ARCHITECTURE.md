# Architecture

By Erik Adler.

The application uses the Next.js App Router and a custom Node HTTP server. The custom server streams media directly from disk, including files added after server startup, and supports HEAD and byte-range requests for phone and TV playback.

SQLite lives at `prisma/dev.db`. Posts have publication timestamps, captions, and ordered media items. Original uploads live at `public/uploads/`; generated thumbnails and H.264/AAC MP4 playback files are retained alongside originals. Original media is preserved during video conversion.

The wall is reverse chronological and loads additional records through a timestamp/id cursor. Intersection observers limit mounted heavy media; one visible wall video plays automatically, with desktop hover/explicit selection priority and playback ownership preventing overlapping local audio. Media overlay buttons and the carousel counter share translucent styling; a viewport-aware inactivity hook fades them after three seconds and holds them visible for keyboard focus or open menus.

Fresh setup explicitly defaults to username/password authentication, using a signed HTTP-only cookie and salted scrypt password hashes in the database. `/admin` contains media uploading; `/admin/settings` contains visitor history, header/account settings, and documentation. Optional Cloudflare mode verifies RS256 Access tokens against the configured issuer/JWKS, application audience, exact owner email, expiry, and public hostname before issuing a CMS session; it does not trust a plain identity header or fall back to passwords in that mode. Changing login credentials invalidates prior sessions. Public readers do not receive admin editing controls. Configure an unpredictable session secret and your own password before server deployment; enable secure cookies behind HTTPS.

Outside visitor records, including public connection IP addresses, are stored locally until manually deleted from authenticated settings. Signed administrator sessions persist owner browser/IP exclusions in `.runtime/visitor-exclusions.json`, and local addresses are skipped; the statistics query also filters matching historical rows. The custom Node server records a local GeoIP estimate immediately, then optionally enriches outside public IPv4/IPv6 with IP2Location.io over HTTPS in the background. A shared in-memory cache/in-flight queue and a persistent private daily counter cap API calls at 900/day; failures retain local estimates. A same-origin `/api/visitor-activity` endpoint verifies signed visitor/visit tickets, limits report rate and duration, and stores cumulative visible-page seconds without creating heartbeat rows. Coordinates, source, duration and lastSeenAt are additive Visit columns; older rows have unknown duration. Only authenticated administrators can refresh historical locations or see map links. Visitor history is paginated and never pruned automatically. Hearts use a signed visitor cookie. Source control contains no archive data or secrets.

Compact share links persist ordered media IDs, photo timing, and repeat choices in private `.runtime/shared-links/<token>.json` files. A keyed digest reuses identical selections without storing giant URLs. `/s/[token]` resolves the current public media, provides Open Graph/Twitter preview metadata, and renders a viewer that requests sound by default, falls back to muted playback when browser policy requires it, and advances without input. Native media controls, playback speed, fullscreen support, and a presentation position slider provide recipient controls. No schema migration or paid API is required; preserve the shared-link files with the archive backups.
